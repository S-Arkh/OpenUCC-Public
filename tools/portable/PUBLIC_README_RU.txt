openUCC — публичный portable-компилятор UnrealScript для Windows x64

ТРЕБОВАНИЯ
Windows x64 и Windows PowerShell 5.1. Python, SDK, Visual Studio и ucc.exe
для запуска не нужны. Распакуйте весь архив в каталог с правом записи.
Игровых пакетов, чужих исходников и зависимостей в комплекте нет.

ПЕРВЫЙ ЗАПУСК
1. Скопируйте подходящий Core.u в Dependencies\Core.u.
   Это обязательный файл пользователя: он определяет целевые типы и версию.
2. Если классам нужны другие пакеты, скопируйте соответствующие .u того же
   клиента в Dependencies. По умолчанию используются все .u из этого каталога,
   кроме Core.u и одноимённого выходного пакета.
3. Положите собственные .uc в каталог Classes; подкаталоги допустимы.
   Для пробы можно скопировать Examples\Example.uc в Classes. Пример требует
   совместимого Core.u и не гарантирует совместимость с любым клиентом.
   Поддерживаются UTF-8 (в том числе с BOM) и UTF-16 LE/BE с BOM; для старых
   локальных кодировок сначала сохраните копию файлов в UTF-8.
4. Двойной щелчок Compile.cmd собирает пакет Interface.
   Другое имя можно выбрать из командной строки:

   Compile.cmd -Package MyPackage
   Compile.cmd -Package MyPackage -SourceDir ".\My Sources"

   Имя пакета и имена зависимостей: латинские буквы, цифры и подчёркивание;
   первый символ — буква или подчёркивание. Имена устройств Windows запрещены.
   Без -SourceDir сначала используется существующий каталог
   Packages\<пакет>\Classes; иначе корневой Classes.
   Не храните в одном Classes классы нескольких независимых пакетов.
5. Результат: Output\MyPackage.u.
   Каждая успешная версия дополнительно сохраняется в Output\<идентификатор>.
   Логи: Logs\<идентификатор>\result.json, compiler.log, stderr.log.
   При ошибке старый Output не является результатом новой попытки.

Для разных клиентов распаковывайте отдельные копии комплекта: не смешивайте
одноимённые Core.u и зависимости.

НАСТРОЙКА ЗАВИСИМОСТЕЙ
Для отдельных пакетов можно задать список в корневом packages.json:

{
  "MyPackage": {
    "mode": "compile",
    "dependencies": ["Engine", "NWindow"]
  }
}

В этом случае исходники по умолчанию находятся в
Packages\MyPackage\Classes, а перечисленные .u должны находиться в Dependencies.
Не указанные в списке зависимости при этой настройке не загружаются.

Необязательный исходный пакет для сохранения поддержанных контрактов:
References\MyPackage.u. Для .uobj используйте -Objects и обязательный одноимённый
References\MyPackage.u: .uobj описывает экземпляры объектов, а не классы .uc.
Для обычной компиляции классов этот режим не нужен. Для пересборки самого Core
исходный Core.u должен находиться в References.

Для автоматизации задайте OPENUCC_NO_PAUSE=1. Компилятор не запускает UCC или
игровые DLL. Успешная компиляция сама по себе не подтверждает эквивалентность
работы в игре. BUILDINFO.json содержит версию, ревизию и хеши файлов комплекта.
