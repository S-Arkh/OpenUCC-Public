# Portable Windows x64

## Public portable release

Архив из раздела Releases содержит `bin/openucc.exe`, запускатель для Windows
PowerShell 5.1, пример класса и лицензию. Игровые пакеты, SDK и чужие исходники
не входят в комплект. Для запуска не нужны Python, Visual Studio или `ucc.exe`.

1. Распакуйте архив в каталог с правом записи.
2. Скопируйте целевой `Core.u` в `Dependencies/Core.u`. Он определяет целевые
   типы и версию пакета. Другие необходимые `.u` того же клиента также поместите
   в `Dependencies`.
3. Поместите свои `.uc` в `Classes` или `Packages/<пакет>/Classes`.
   Подкаталоги поддерживаются. Можно скопировать `Examples/Example.uc` в
   `Classes`. Исходники одного каталога должны относиться к одному пакету.
   Поддерживаются UTF-8 с BOM или без него и UTF-16 LE/BE с BOM. Другие
   кодировки следует предварительно преобразовать в UTF-8.
4. Запустите `Compile.cmd -Package MyPackage`. Двойной щелчок без параметров
   собирает пакет `Interface`. Для каталога с исходниками вне комплекта
   используйте `-SourceDir "путь к исходникам"`.
5. Проверьте `Logs/<идентификатор>/result.json` и `stderr.log`. При успехе
   результат находится в `Output/MyPackage.u`, а отдельная копия — в
   `Output/<идентификатор>`. При ошибке прежний результат не заменяется и не
   является результатом последней попытки.

Имя пакета и зависимости должно начинаться с латинской буквы или подчёркивания
и содержать только латинские буквы, цифры и подчёркивания. Зарезервированные
имена устройств Windows для выходного пакета запрещены.

Целевой профиль определяется переданным `Core.u`. Используйте отдельный
распакованный комплект для каждого клиента и не смешивайте одноимённые
зависимости разных клиентов.

### Выбор зависимостей

По умолчанию используются все `.u` из `Dependencies`, кроме `Core.u` и файла
с именем выходного пакета. Для явного выбора добавьте запись в `packages.json`:

```json
{
  "MyPackage": { "mode": "compile", "dependencies": ["Engine", "NWindow"] }
}
```

Для такой записи исходники по умолчанию берутся из
`Packages/MyPackage/Classes`; также можно указать `-SourceDir`. Необязательный
`References/MyPackage.u` позволяет использовать поддержанные контракты
исходного пакета.

Параметр `-Objects` включает компиляцию `.uobj` и требует соответствующий
`References/MyPackage.u`. Для обычных классов `.uc` этот режим не нужен.
Для пересборки `Core` исходный `Core.u` должен находиться в `References`.
Подробнее о формате объектов — в [OBJECT_PACKAGES.md](OBJECT_PACKAGES.md).

Для автоматизированного запуска можно задать `OPENUCC_NO_PAUSE=1`. Успешная
компиляция или проверка структуры сама по себе не гарантирует работу в игре.

## Manual GitHub release

После размещения `.github/workflows/release-openucc.yml` в основной ветке:

1. Откройте **Actions → Release OpenUCC → Run workflow** и выберите ветку.
2. Укажите версию без начальной `v`, например `0.1.0-rc.1`. Для предварительной
   версии оставьте `prerelease` включённым; для стабильной версии выключите.
   Версия с суффиксом требует `prerelease`.
3. Workflow закрепляет выбранную ревизию, собирает Windows x64, запускает CTest
   и Python-тесты, затем распаковывает архив и проверяет его на синтетических
   входных данных. Упаковщик также проверяет файлы на типичные персональные
   пути и признаки учётных данных. При ошибке проверок публикация не выполняется;
   автоматический поиск не заменяет проверку содержимого.
4. В GitHub Releases публикуются `OpenUCC-<версия>-windows-x64.zip` и
   `SHA256SUMS.txt`, а также создаётся тег `openucc-v<версия>`.
   `BUILDINFO.json` внутри архива содержит ревизию и хеши файлов комплекта.

Существующий тег или релиз останавливает выпуск. Если ошибка возникла после
создания тега, могут остаться тег и черновик релиза: проверьте их перед
повторным запуском. Для workflow нужны доступные GitHub Actions и разрешение на
запись содержимого репозитория.

### Локальная сборка архива

Нужны Windows x64, Visual Studio с C++17, CMake и Python 3.10+. Из корня чистого
клона:

```powershell
cmake -S . -B build-release -G "Visual Studio 17 2022" -A x64
cmake --build build-release --config Release
ctest --test-dir build-release -C Release --output-on-failure
python -B -m unittest discover -s tests -p "test_*.py"
python -B tools/package_portable.py --version 0.1.0-rc.1 --revision (git rev-parse HEAD) --exe build-release/Release/openucc.exe --fixture-tool build-release/Release/openucc_portable_fixture.exe --out local/new-portable-release
```

Выходной каталог упаковщика не должен существовать. Проверенные файлы окажутся
в его подкаталоге `publish`. Перед распространением сравните хеш ZIP с
`SHA256SUMS.txt`. Упаковщик включает только файлы из явного списка и не копирует
пользовательские зависимости или исходники.
